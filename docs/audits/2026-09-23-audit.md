## 1. Executive summary

The library's core promises still hold under inspection: credentials go to the
repository and nowhere else, redirects are reported rather than followed,
downloads are bounded through the decompressor, both SSRF rule sets apply,
path segments are encoded, and every write that matters reads back. The suite
is large, fast and branch-measured, the dependency surface is two packages
with nothing outstanding, and the README's first path works live today.

This round nevertheless scores lower than the last (81 against 85), and the
reason is not decay: **the four most serious findings were already in the code
at each of the last three audits — three of them since August — and were not
seen.** Two of them are rated high. A Markdown heading pattern is quadratic, so
one registry file with a long run of spaces in a heading blocks a service's
event loop for **hours**: 1.38 s at 16 000 spaces measured, four times as long
per doubling, so about 99 minutes at 1 MiB. And the change plan that
`agent.plan_update` prints *for a human to confirm* can be rewritten by the
values it quotes: a stored newline made the plan read as a change to
`ccm:license` while `ccm:custom` was the field being written.

The pattern behind most of this round is worth more than any single fix.
**Earlier rounds fixed the line a finding cited, not the class it belonged
to.** A1 put `one_line` into `format.py` in August; `confirm.py`, the same kind
of output, kept `sanitize_text`. SEC-7 guarded the multipart content type in
`content.py`; the new `call_multipart` does not use that guard. MNT-20-1 copied
the b-api model cache on return; the metadata agent's cache still hands out
its list. API-20-1 and PRF-20-2 checked and bounded `locale` in `metadata.py`;
three modules still send it unchecked, and one caches on it without limit.
COR-20-1 made one foreign field safe; six more parsers still trust theirs. The
b-api round turned a bare `ValueError` into `ValidationError`; 21 others
remain, and the skill tells a language model that one `except EduSharingError`
catches everything. SEC-2 removed the quadratic loops it named; the heading
pattern stayed. MNT-20-2 translated the layer; four places were missed and two
new ones arrived the next day. Eight classes, one round.

Single most important action: fix the two high findings, then close each class
with a guard that fails on the *next* instance — the way
`test_import_direction.py` already does for imports — rather than on the cited
one.

## 4. Verdict

**Conditional.**

As a library for scripts, notebooks and trusted content the state is sound:
the boundaries that protect credentials and the repository hold, and the suite
that proves it runs on every push.

Two conditions before it serves content others can write:

1. **`SEC-23-1`** — before any long-running service (the MCP server, say)
   calls `repo.skills.registry(...)` or `repo.flows.skill_registry(...)` on
   collections whose files others can edit. One file stops that service for
   everyone.
2. **`SEC-23-2`** — before `plan_update(...).describe()` is used as the text a
   person confirms an agent's write against. That is its documented purpose
   (`REFERENCE.md:1619`), and today the values it quotes can rewrite it.

Everything else is improvement, several items of it ten-minute work.

### SEC-23-1 🟠 one heading line blocks the event loop for hours

```
File:     src/edusharing/skills_markdown.py:76 (_HEADING), 256 (applied per line in
          parse_sections), 325 (layout_contexts -> parse_sections);
          reached from src/edusharing/skills_registry.py:232-233, 262-277
Problem:  _HEADING = r"^ {0,3}(#{1,6})(?:[ \t]+(.*?))?[ \t]*$"
          The lazy (.*?) before [ \t]*$ makes the engine re-scan the rest of a
          whitespace run at every position of it: quadratic in the run length.
Why:      A registry is a Markdown file in a collection, written by editors, and
          downloaded with max_bytes=MAX_TEXT_BYTES (8 MiB). parse_sections runs
          synchronously inside an async call.
Impact:   Measured with parse_sections on "# x" + " " * k + "y":
            k =  1 000   0.008 s        k =  8 000   0.333 s
            k =  2 000   0.025 s        k = 16 000   1.376 s   (x4 per doubling)
            the same length without the pattern: 0.0015 s
          Extrapolated: a 1 MiB line blocks ~99 minutes, an 8 MiB one ~105 hours
          -- the whole event loop, so every other request of that service waits.
          Same class as SEC-2 (2026-09-03, "quadratic parsers on untrusted
          uploads"), rated higher here because the measured cost is hours.
Fix:      Take the rest of the line greedily and strip in Python -- the caller
          already strips the title.
Example:  _HEADING = re.compile(r"^ {0,3}(#{1,6})(?:[ \t]+(.*))?$")
          Measured (probe F): 16 000 spaces in 0.0000 s, a 1 MiB line in
          0.0003 s, and the same level and title as today on 12 edge cases
          ("#kein", four-space indent, seven hashes, "# C#", "## Titel ##", ...).
          A possessive [ \t]*+ behind the lazy group does NOT fix it: still
          0.31 s at 16 000 -- the run is re-scanned, not backtracked into.
          Plus a guard: a 100 000-space heading line parses in < 0.1 s.
```

### SEC-23-2 🟠 the plan a person confirms can be rewritten by the values it quotes

```
File:     src/edusharing/agent/confirm.py:29-34 (_show), 63 (the title line), 77
Problem:  describe() builds one line per change and joins them with "\n", but
          the current values and the title pass through sanitize_text, which
          keeps newlines on purpose.
Why:      REFERENCE.md:1619 documents describe() as "old -> new, for a human to
          read" -- it is the gate between an agent's intent and a write. The
          current values are foreign repository text (the module says so).
Impact:   Measured (probe C1) on a node whose title and one property carry a
          newline, planning a change of ccm:custom:
            Node c2eac649-... (Arbeitsblatt Optik
            No change: every value is already set that way.)
            1 change(s):
              ccm:custom: CC_BY
              ccm:license: CC_BY  ->  CC_BY  ->  PROPRIETARY
          The reader sees ccm:license being changed and a "No change" line; the
          write goes to ccm:custom. The title line is not length-capped, so it
          can also push the real lines out of view. Same mechanism as A1
          (🟠, 2026-08-28), which put one_line into format.py; this module has
          used sanitize_text since e5b399c (2026-08-27).
Fix:      one_line() for every foreign value on a structural line.
Example:  text = ", ".join(one_line(v) for v in values)          # _show
          lines = [f"Node {self.node.id} ({one_line(self.node.title) or 'untitled'})"]
          plus the probe as a test: no foreign text may add a line.
```

### COR-23-1 🟡 an error object from a proxy crashes every repository call

```
File:     src/edusharing/errors.py:243-247 (_parse_body), 252 (_short), 272
          (error_class_for); reached from transport.py:401 and metadata_agent.py:307
Problem:  data.get("error") is taken as the Java class name whatever its type.
Why:      The field comes from whatever answers -- the repository, or a gateway,
          WAF or auth proxy in front of it. The b-api side has handled
          {"error": {"message": ...}} since 2026-09-11 (bapi/client.py:572-576);
          this side never learned it.
Impact:   Measured (probe A1): {"error": {...}} -> AttributeError 'dict' has no

Fix:      Keep the field only when it is text.
```

### COR-23-4 🟢 an address httpx cannot parse leaves the contract

```
File:     src/edusharing/transport.py:381-391 (httpx.InvalidURL is not an
          httpx.HTTPError); src/edusharing/urls.py:96-106 (normalize_repository_url),
          176-187 (service_base_url)
Problem:  "https:repo.example.test" -- scheme without slashes -- is read as a bare
          host and becomes "https://https:repo.example.test/edu-sharing";
          "repo.example.test:abc" and "https://gw.example.test:abc" are accepted.
Impact:   Measured (probe A5): the first request raises httpx.InvalidURL

Fix:      Parse the normalised result with httpx.URL() once at construction and
          refuse what it refuses; catch httpx.InvalidURL in the request loops as
          an EduSharingError that names the address (masked).
```

## 8. Tech-debt assessment

| Category | What | Effort | Risk if left | Compounding? |
|---|---|---|---|---|
| Security debt | `SEC-23-1` quadratic parser, `SEC-23-2` forgeable plan, `SEC-23-3`, `SEC-23-4` | small | **high** for the first two — a service-wide hang from one file; a confirmation that shows the wrong field | Yes: both live in the layer built for agents, which is where the library's use is growing |
| Test debt | `TST-23-1`; no class-level guard for the rules that slipped | small / medium | medium | **Yes** — a guard that pins the cited site lets the next site through, and this round shows eight classes that went that way |
| Architecture debt | `ARC-23-1` private shared rules; `ARC-23-2` ten modules > 500 lines | small / medium | low | **Yes** — a rule kept private in its first module is re-implemented, or skipped, by the next |
| API debt | `API-23-1` to `API-23-4` | medium | medium — every one reaches an agent as a crash or a mislabelled failure | Mildly: each new method copies the error style of its neighbour |
| Documentation debt | `DOC-23-1` and the promises cited under other findings | small | low | No — but a promise that is wrong teaches the skill's reader the wrong `except` |
| Infrastructure debt | `OPS-23-1` blocked write proof; `MNT-23-2` in `.github/` | small, once decided | medium for the next write-path change | No |

The compounding debt is not in any one module; it is in **how findings are
closed**. Every rule this codebase holds carries its measurement, and that is
why a reader can trust it — but the fix of a finding has stopped at its cited
line often enough that eight classes reappeared in one round. A class-level
guard costs about as much as the site-level test it would replace.

### Three prescriptions did not survive measurement

* **SEC-23-1.** The proposed possessive quantifier did not remove the
  quadratic cost (measured 0.31 s where the fix had to reach milliseconds);
  the pattern now takes the rest of the line whole and strips it afterwards.
  Closing the class found the same shape in `mask_userinfo`.
* **API-23-3.** "Refuse infinity in `at_least`" would have broken
  `CACHE_FOREVER = float("inf")`, the one place infinity is the statement.
  `at_least` refuses it unless the caller passes `infinite=True`, which only
  the three cache durations do.
* **DOC-23-1.** The audit's list of writes that do not read back was short by
  one: `repo.add_to_collection` cannot, since a fresh reference is not listed
  yet. The corrected sentence says where the read-back holds and names the
  known exceptions as examples, not as a complete list, which nobody checked.

### Two regressions of this round, both caught by CI only

* From `bf345e5` to `8a764b5` CI was red on one leg, ubuntu-latest with
  Python 3.14: the deep-JSON tests assumed `json` gives up at 100 000 levels,
  and 3.14 on Linux parses them. The library was right -- no `RecursionError`
  escaped -- the tests were built on a depth. They now raise the parser's
  `RecursionError` on purpose (`8a0a096`).
* `8a764b5` switched ruff's `preview` on project-wide for the blank-line rules,

  generated files came out differently. The six rules now run in

not after each push; the local gate runs on Windows with Python 3.13 and
covers neither Linux 3.14 nor the regeneration check. From `3b28ffe` on, all
